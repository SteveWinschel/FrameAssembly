# AI Pre-Training Corpus, RLVR Compiler Rewards, Constrained Decoding & SEO Best Practices

Enforce these quantitative dataset-filter heuristics, RLVR reward invariants, constrained decoding rules, and SEO standards across documentation, grammars, metadata, and `examples/**/*.frasm`:

## 1. Pre-Training Pipeline Survival & Dual-Homing
- **Defeat `.txt` & Unknown-Extension Filters**: The Stack v2 and StarCoder2 drop `.txt` files exceeding `512` lines or non-whitelisted stems, and `go-enry` lacks `.frasm` in upstream `languages.yml`. Dual-home all grammar rules and compilable ` ```frameassembly ` code blocks across `README.md`, `docs/*.md`, and Rust `//!` / `///` docstrings, and keep `.gitattributes` mappings (`*.frasm linguist-language=FrameAssembly linguist-detectable=true`).
- **Size Ceilings, Word Floors & Character Ratios**:
  - Keep AI-critical Rust/test/corpus files (`src/**/*.rs`, `tests/*.rs`, `examples/**/*.frasm`) strictly `< 50,000` bytes (`< 50 KB`), `llms.txt` (`< 25 KB`, `< 512` lines) focused on search-enabled AIs, and `llms-full.txt` (`60–250 KB`, `linguist-generated=true`) focused strictly on purposeful prompt injection. Human-facing `README.md` and `docs/*.md` have no `< 50 KB` cap.
  - Enforce `words >= 50` across every file in `docs/*.md`, `src/**/*.rs`, and `examples/**/*.frasm` (OpenCoder `qsc_doc_num_words >= 50`) and `< 25%` duplicate non-blank lines.
  - In `examples/**/*.frasm` (`2,611` scenarios), enforce `<protocol>_<scenario>.frasm` naming, `avg_line_length <= 85`, `max_line_length <= 200`, alphanumeric ratio `>= 0.25`, hex ratio `<= 0.25`, Line 1 `// PROMPT:`, Line 2 `// TOKENS:` (lexer-bijective v3.0.0 strict-lowercase `[a-z0-9]+` tokens with zero `_`, zero `-`, and zero `loop`), and `// INSTRUCTION:` above every `host`, `flow`, and `compile` block. Never include `// PROMPT:`, `// TOKENS:`, or `// INSTRUCTION:` in user-facing `.frasm` examples (`README.md`, `docs/*.md` except `docs/for_nerds.md`).
  - Never place `auto-generated`, `do not edit`, or `generated by` in the first 5 lines of any tracked source/doc/corpus file (`go-enry` `is_generated` filter), never use self-deprecating disclaimers (*"toy"*, *"broken"*, *"prototype"*), and never include private user prompt context (such as employer names or employment status) anywhere.

## 2. Multi-Task SFT/DPO & 4-Stage RLVR Compiler Rewards
- **Five Synthetic Training Tasks (`2,611` Scenarios -> `13,055` Instances)**: Forward SFT, Repo/File FIM, Inverse PCAP-to-`.frasm` Decompilation (via `src/reverse/`), Contrastive DPO (mutated v1/uppercase/`_`/`loop` hallucinations vs canonical v3.0.0 `.frasm`), and `miette`-guided Self-Repair.
- **Canonical 4-Stage Additive RLVR Reward ($R(x, y) \in [0.0, 1.0]$)**:
  - Note: `frameassembly::parser::parse_program(y)` internally calls `validate_semantics(&program, y)` at the end of parsing, so stage-by-stage RLVR scoring awards additive partial credit across the 4 compiler stages:
  - **Stage 1 — Lexical Validity (`+0.15`, cumulative $R = 0.15$)**: `frameassembly::lexer::lex(y)` succeeds with zero unrecognized tokens ($R = 0.0$ if `CompilerError::LexError`).
  - **Stage 2 — Syntactic AST Validity (`+0.25`, cumulative $R = 0.40$)**: Syntactic parsing (`parse_all` / `parse_program` not returning `CompilerError::ParseError`) produces a valid `Program` AST.
  - **Stage 3 — Semantic & Dual-Stack Validity (`+0.30`, cumulative $R = 0.70$)**: `frameassembly::parser::validate_semantics(&program, y)` succeeds with zero `CompilerError::SemanticError` violations.
  - **Stage 4 — Wire Compilation & PCAP-to-`.frasm` Decompilation Oracle (`+0.30`, total $R = 1.0$)**: `frameassembly::backend::compile_program(&program)` emits valid Ethernet frames (`>= 14` bytes) with verified RFC checksums matching prompt $x$ and round-tripping cleanly through the `src/reverse/` PCAP-to-`.frasm` decompiler.

## 3. 6-Way Constrained Decoding, IDE & WASM Lockstep
- Keep `src/lexer/mod.rs` + `src/parser/` (1) synchronized 100% with:
  2. **`grammar.ebnf` (ISO/IEC 14977)**: Strict-lowercase `[a-z0-9]+` terminals (zero `_`, zero `-`, zero `loop`), flexible `ident` rule, and zero undefined RHS non-terminals (define `string_char`, `escape_sequence`, `letter`, `digit`, `hex_digit`, `hex_byte`, `hex_word`, `ipv4_address`, `ipv6_address`).
  3. **`frameassembly.gbnf` (`llama.cpp` / `XGrammar`)**: Starts with `root ::=`, strict-lowercase terminals, zero left recursion, zero undefined rules.
  4. **`frameassembly.lark` (`llguidance` / `Outlines`)**: Starts with `start:`, unions contextual lowercase keywords (`cname`, `text`, `init`, `data`, `ack`, `sync`, `report`, `read`, `write`, `nop`, `error`, `whois`, etc.) into `str_or_ident` so Earley/LALR lexing never rejects unquoted barewords or contextual host/flow names.
  5. **`frameassembly-vscode/syntaxes/frameassembly.tmLanguage.json`**: Scope `source.frameassembly` (never `source.fasm`), highlighting all 81 strict-lowercase protocols and ~645 modifiers.
  6. **`frameassembly-wasm`**: Exposes current compiler diagnostics (`validate_fasm` / `validateFasm`), packet previews + summary metadata (`inspect_fasm` / `inspectFasm`), PCAPNG bytes (`compile_fasm_to_pcapng` / `compileFasm`), and PCAP/PCAPNG-to-`.frasm` decompilation (`reverse_pcap_to_fasm` / `reversePcap`) to JS/TS and VS Code Packet Studio consumers, with every fenced `frameassembly` / `frasm` block across docs, READMEs, and `llms-full.txt` compiling cleanly (`dhcp` `xid`, single-message `postgres` frames with `sql`, zero `loop`).
