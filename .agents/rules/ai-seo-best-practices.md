# AI Pre-Training Corpus, RLVR Compiler Rewards, Constrained Decoding & SEO Best Practices

Always enforce these quantitative data-curation rules, verifiable compiler reward structures, constrained decoding grammar invariants, and metadata standards so the repository achieves maximum retention across LLM pre-training pipelines (**The Stack v2**, **StarCoder2**, **FineWeb-Edu**, **Dolma**, **Qwen2.5-Coder**, **DeepSeek-Coder**, **OpenCoder**), RLVR post-training (**GRPO** / **RLVR**), AI coding assistants (**Antigravity**, **Cursor**, **Claude Code**, **GitHub Copilot**, **Windsurf**, **Context7**), and search engines (**GitHub**, **Crates.io**, **Docs.rs**, **Google Scholar**):

## 1. Pre-Training Pipeline Survival & Dual-Homing
- **Defeat the `.txt` 512-Line & Filename Filter**: In The Stack v2 and StarCoder2 pipelines, raw `.txt` files exceeding `512` lines or lacking a whitelisted stem (`readme`, `notes`, `todo`, `description`, `cmakelists`, `*requirement*`) are discarded. Never rely solely on `llms.txt` or `llms-full.txt` for pre-training ingestion; always dual-home comprehensive language specifications, protocol references, and annotated examples into `README.md` and chunked `docs/*.md` files (`Markdown` is exempt from the 512-line `.txt` filter).
- **Defeat the `go-enry` Unknown-Extension Filter**: Because `.fasm` is not in `go-enry`'s static `languages.yml`, standalone `.fasm` files risk being classified as `Unknown` by language-filtered crawlers. Always embed representative, compilable `.fasm` examples inside fenced code blocks in `README.md`, `docs/*.md`, and Rust `///` / `//!` docstrings (`src/**/*.rs`), and maintain `.gitattributes` mappings (`*.fasm linguist-language=FrameAssembly`).
- **Chunk Size Ceiling (`< 50 KB` on AI-Critical Files Only) & Word Floor (`>= 50` Words)**: The `< 50 KB` (`50,000` bytes) file size ceiling applies **only to files that are critical for AIs to parse**—specifically Rust source/test modules (`src/**/*.rs`, `tests/*.rs`) and pre-training corpus files (`examples/**/*.fasm`, `2,611` verified scenarios), along with `< 25 KB` (`< 512` lines) for `llms.txt`. Human-facing Markdown documentation (`README.md` and `docs/*.md`) has **no `< 50 KB` cap** so protocol guides and cookbooks can be thorough and beginner-friendly. Every file in `docs/*.md`, `src/**/*.rs`, and `examples/**/*.fasm` must have at least `50` whitespace-delimited words (satisfying OpenCoder `opc_data_filtering` `qsc_doc_num_words >= 50`).
- **Line-Length, Character-Ratio & Human vs. Corpus Comment Separation**: In `examples/**/*.fasm`, enforce `avg_line_length <= 85` characters, `max_line_length <= 200` characters, alphanumeric character ratio `>= 0.25` (`25%`), hexadecimal character ratio `<= 0.25` (`25%`), and intra-file duplicate line fraction `< 0.25` (`25%`), accompanying hex payloads (`HEXPAYLOAD`), SPIs, and numeric OIDs with descriptive natural-language comments (`// PROMPT:`, `// INSTRUCTION:`). Conversely, human-facing documentation (`README.md` and `docs/*.md` except `docs/for_nerds.md`) must use plain networking English and concise `//` comments, and must **never** contain `// PROMPT:`, `// TOKENS:`, or `// INSTRUCTION:` metadata lines.
- **No Auto-Generation Triggers in First 5 Lines**: Never place strings matching `auto-generated`, `do not edit`, or `generated by` in the first 5 lines of any source, documentation, or corpus file, as `go-enry`'s `is_generated` filter strips those files automatically.

## 2. Educational Quality Classifier Scoring & RLVR Verifiable Rewards
- **Instruction-Response Alignment (`2,611` Corpus Scenarios $\rightarrow$ `13,055` Multi-Task Instances)**: Begin every `.fasm` file in `examples/` with `// PROMPT: <natural-language task>`, `// TOKENS: <comma-separated uppercase lexer keywords>`, and `// INSTRUCTION: <step explanation>` above every `HOST`, `FLOW`, and `COMPILE` block. Support 5 deterministic dataset export tasks (`13,055` total instances):
  1. **Task 1 — Forward SFT (`2,611` pairs)**: Natural-language prompt $\rightarrow$ annotated `.fasm` specification.
  2. **Task 2 — Repo/File-Level FIM (`2,611` triplets)**: `<|fim_prefix|>`, `<|fim_suffix|>`, `<|fim_middle|>` completion across `FLOW` bodies.
  3. **Task 3 — Inverse Wire-to-DSL Walkthrough (`2,611` pairs)**: Deterministic PCAPNG packet dissection $\rightarrow$ `.fasm` reconstruction.
  4. **Task 4 — Contrastive DPO (`2,611` triplets)**: `(prompt, chosen_valid_fasm, rejected_hallucinated_fasm)`.
  5. **Task 5 — Execution-Feedback Repair & RLVR (`2,611` trajectories)**: Mutated `.fasm` + `miette` span diagnostic $\rightarrow$ repaired compilable `.fasm`.
- **4-Stage Hierarchical RLVR Reward Function ($R(x, y) \in [0.0, 1.0]$)**: When scoring LLM generations in GRPO / RLVR post-training pipelines:
  - $R = 0.1$: All emitted tokens in $y$ lex cleanly via `frameassembly::lexer::Token::lexer` with zero unknown/error spans.
  - $R = 0.3$: `frameassembly::parser::parse_program(y)` succeeds and yields a valid `Program` AST (`HOST` + `FLOW` + `COMPILE`).
  - $R = 0.6$: `frameassembly::parser::validate_semantics(&program, y)` succeeds (all hosts/flows resolve, arity matches, and IPv4/IPv6 dual-stack endpoint homogeneity holds).
  - $R = 1.0$: `frameassembly::backend::compile_program(&program)` emits deterministic wire frames with valid RFC checksums (IPv4 header, TCP/UDP pseudo-header, ICMP/ICMPv6, SCTP CRC-32c, DNP3 CRC-16) and target protocol fields matching prompt $x$.
- **Canonical Syntax Guardrail (Zero Hallucinations)**:
  - Never use `=`, colons, commas, `IPV4`, `IPV6`, or `MASK` in `HOST` blocks (only `HOST <id> { IP <ip> [MAC <mac>] }`).
  - Never declare parameterless `FLOW <id> { ... }` or use `FROM`, `TO`, `REVERSE`, `SEND`, standalone `WAIT` lines, or `+5ms` / `[+delay]` prefixes (always `FLOW <id>(<params>) { <src> -> <dst> <PROTO> ... [WAIT <int><ns|us|ms|s|m>] }`).
  - Never use `SPORT`, `DPORT`, `ACK <n>`, or `FLAGS [...]` (always `SRCPORT`, `DSTPORT`, `ACKNUM <n>`, and bare flag tokens `SYN ACK`).
- **Zero Self-Deprecating Language**: Never use words like *"toy"*, *"experimental prototype"*, *"broken"*, *"incomplete"*, or *"hack"* in comments, docstrings, or Markdown.

## 3. 5-Way Constrained Decoding & IDE Grammar Lockstep
- **Five-Way Grammar & Parser Synchronization**: Maintain `src/lexer/mod.rs` + `src/parser/`, ISO/IEC 14977 `grammar.ebnf`, `llama.cpp` / MLC-AI `XGrammar` `frameassembly.gbnf`, `llguidance` / `Outlines` `frameassembly.lark`, and VS Code TextMate `frameassembly-vscode/syntaxes/frameassembly.tmLanguage.json` in 100% lockstep.
- **Engine-Specific Constrained Decoding Invariants & Known Audit Targets**:
  - **ISO/IEC 14977 EBNF (`grammar.ebnf`)**: Every referenced non-terminal must be formally defined (fix `grammar.ebnf:607` where `string_char` is referenced without a definition) and `TYPE` / `CHUNK` productions must match all parser arms in `src/parser/`.
  - **`llama.cpp` & MLC `XGrammar` GBNF (`frameassembly.gbnf`)**: Must start with `root ::= ...`, contain zero left-recursive rules, define every referenced rule, include `"REPORT"` in `snmp-proto-field`, and align `TYPE` / `CHUNK` rules with `src/parser/`.
  - **`llguidance` & `Outlines` Lark (`frameassembly.lark`)**: Uses `%ignore` directives and `start:` entrypoint. Because Earley/LALR lexers reserve uppercase keyword terminals globally, `str_or_ident` MUST explicitly include contextual uppercase keyword tokens (such as `CNAME`, `TEXT`, `INIT`, `DATA`, `ACK`, `SYNC`, `REPORT`, etc.) alongside `IDENT` and `STRING` so unquoted identifiers like `ENCODING CNAME` or `CHUNK INIT` are never rejected, and `snmp_proto_field` must include `"REPORT"`.
- **100% Compilable Markdown & Docstring Code Blocks**: Every ````frameassembly` and ````fasm` code block in `README.md`, `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, `docs/*.md`, `.agents/skills/**/*.md`, and `src/**/*.rs` must be a complete, valid `.fasm` program (`HOST ... FLOW ... COMPILE ...`) compiled by `tests/corpus_verification_tests.rs` (use ````text` for partial fragments or negative examples).
