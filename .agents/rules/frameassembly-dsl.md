# FrameAssembly DSL & Compiler Architecture Guidelines

- **Expose Protocol Fields & Wire Completeness**: When adding or updating network protocols in the FrameAssembly DSL, avoid hardcoding protocol parameters (e.g., Engine Boots, Context Name in SNMP). Always expose these as optional configurable fields in the DSL and wire every AST `*Spec` field parsed in `src/parser/` into `src/builders/`.
- **L7 Builder Return-Tuple Preservation (`src/backend/l7_dispatch.rs`)**: Always preserve builder-returned dynamic ports and multicast target IPs in `l7_dispatch.rs`—including `DHCP` (`(pkt, sport, dport)` with `546/547` for DHCPv6 vs `68/67` for DHCPv4), `MDNS` (`(payload, target_ip, 5353)` with `224.0.0.251` / `ff02::fb`), `PTP` (`(result, dport)` with `319` Event vs `320` General), and `RADIUS` (`(pkt, dport)` with `1812` Auth vs `1813` Accounting)—never discarding them in favor of static defaults.
- **Keep Keyword Surface Minimal**: Since FrameAssembly targets network technicians (non-programmers), avoid adding redundant keyword aliases (e.g., use a single canonical `TTL` and `DSCP` keyword across IPv4 and IPv6 rather than adding `HOPLIMIT`, `TRAFFICCLASS`, or `TOS`). Ignore version-specific optional fields (like `FLOWLABEL` on IPv4) when a dual-stack flow runs over another protocol version.
- **Smart RFC-Compliant Defaults**: Automatically derive standard wire defaults when optional fields are omitted (e.g., RFC 2464 `33:33:xx:xx:xx:xx` and RFC 1112 `01:00:5e:xx:xx:xx` Ethernet MACs for multicast hosts, IPv6 Hop Limit `255` for NDP/VRRPv3, and RFC 3584 `0.0.0.0` SNMPv1 `agent-addr` over IPv6).
- **Support Modern Standards**: Always research and implement modern RFCs (e.g., RFC 7860 for SNMPv3 USM SHA-2, RFC 5798 for VRRPv3 pseudo-header checksums, RFC 9000 §16 for QUIC 2-byte varint lengths) rather than stopping at legacy standards.
- **Dependency Hygiene**: Never add or use unmaintained crates in `Cargo.toml`.
- **5-Way Grammar, Lexer & Editor Lockstep**: Whenever adding or updating DSL keywords, protocols, or grammar rules, keep `src/lexer/mod.rs` $\leftrightarrow$ `src/parser/` $\leftrightarrow$ `grammar.ebnf` $\leftrightarrow$ `frameassembly.gbnf` $\leftrightarrow$ `frameassembly.lark` $\leftrightarrow$ `frameassembly-vscode/syntaxes/frameassembly.tmLanguage.json` in 100% lockstep, and synchronize `README.md`, `llms.txt`, `llms-full.txt`, and `docs/*.md` (`< 50 KB` per file). Never include self-deprecating "experimental/broken prototype" disclaimers.
- **Unified `<layer>/<protocol>` Architecture (`src/` & `examples/`)**: Maintain strict structural symmetry across `src/{ast,parser,builders}/{l2,l3,l4,l7}/<protocol>.rs` (with `src/builders/l7/snmp/` and folder modules `src/lexer/` and `src/backend/`) and `examples/{l2,l3,l4,l7}/<protocol>/<protocol>_<scenario>.fasm` (with `examples/l7/snmp/{snmpv1,snmpv2c,snmpv3}/` and `examples/topologies/`).
- **Examples Corpus Format & Line-Length Guardrails**: When adding `.fasm` files under `examples/<layer>/<protocol>/`, use descriptive `<protocol>_<scenario>.fasm` filenames without numeric prefixes, include `// PROMPT: ...` on line 1, `// TOKENS: ...` on line 2, and `// INSTRUCTION: ...` comments above every `HOST`, `FLOW`, and `COMPILE` block, and enforce `words >= 50`, `avg_line_length <= 85`, and `max_line_length <= 200`.
- **Intra-File Repetition & Context-Window Hygiene**: Keep individual `.rs` and `docs/*.md` files under `40–50 KB` (`< 12K tokens`) by splitting large modules into submodules. In test suites (`tests/*.rs`), diversify host names, IP addresses, flow names, and assertions across test functions so intra-file duplicate lines stay strictly below `25%`, and never silently swallow parse or backend errors in E2E test runners.
- **AST Syntax-Mapping Docstrings & Actionable Parser Diagnostics**: Every AST node and protocol `*Spec` struct in `src/ast/{l2,l3,l4,l7}/<protocol>.rs` must include a `/// Syntax mapping: \`...\`` docstring and `#[doc(alias = "...")]` attributes binding the Rust type to its concrete `.fasm` grammar. All parser error paths in `src/parser/` must include the offending token and expected grammar context (`validate_semantics(&program, &source)`).
- **Protocol-Scoped Sub-Keywords & Zero Cross-Protocol Shadowing**: Scope protocol-specific sub-keywords via `dispatch_protocol_field` in `src/parser/fields.rs` (so `cut_err` or 0-arg flags on shared tokens like `VALUE`, `VERSION`, `STATUS`, `TOKEN`, `MSGID`, `GROUP`, `DATA`, `COOKIE`, `RESPONSE`, `REPLY`, `KEEPALIVE` never shadow other protocols) and include all keyword tokens in `parse_spanned_ident` so they can be used freely as `HOST`, `FLOW`, or flow parameter identifiers.
- **Canonical Syntax Only (Anti-Hallucination Ban List)**: Never use `=`, colons, commas, `IPV4`, `IPV6`, or `MASK` in `HOST` blocks (only `HOST <id> { IP <ip> [MAC <mac>] }`). Never declare parameterless `FLOW <id> { ... }` or use `FROM`, `TO`, `REVERSE`, `SEND`, `[+delay]` / `+5ms` prefixes, standalone `WAIT` lines, `SPORT`, `DPORT`, `ACK <n>`, or `FLAGS [...]` (always `FLOW <id>(<params>) { <a> -> <b> <PROTO> ... [WAIT <int><ns|us|ms|s|m>] }`, `SRCPORT`, `DSTPORT`, `ACKNUM <n>`, and bare flag tokens `SYN ACK`). Never write bare `COMPILE` or argumentless flow calls inside `COMPILE { <flow>(<hosts>) }`.
- **1 Statement = 1 Frame & Shared 4-Tuple TCP State**: Every TCP-based L7 protocol statement must emit a single TCP `PSH ACK` frame on that protocol's well-known default port (unless overridden) and share 4-tuple TCP sequence/ack state with raw `TCP` statements on the same connection.
- **Exhaustive Per-Protocol Corpus & Markdown Block Verification**: All **`2,611`** `.fasm` files (`13,055` synthetic multi-task training instances) across the 82 directories under `examples/{l2,l3,l4,l7,topologies}/` and all ````frameassembly` / ````fasm` blocks in `README.md`, `docs/*.md`, `src/**/*.rs`, and `.agents/skills/**/*.md` must maintain strict `PROMPT`/`TOKENS` (lexer-bijective)/`INSTRUCTION` header discipline and 100% PCAPNG compilation verified by `tests/corpus_verification_tests.rs`.
- **Full 81-Protocol Native Coverage**: The DSL natively supports all 81 protocol keywords across IPv4 and IPv6: ARP, VLAN, QINQ, LLDP, STP, LACP, EAPOL, MPLS, ICMP, NDP, IGMP, MLD, GRE, VXLAN, GENEVE, IPSEC, ESP, AH, IKEV2, WIREGUARD, OSPF, BGP, RIP, VRRP, HSRP, PIM, BFD, OPENFLOW, TCP, UDP, SCTP, SNMP1, SNMP2, SNMP3, DNS, MDNS, DHCP, NTP, PTP, RADIUS, TACACS, SYSLOG, NETFLOW, IPFIX, SFLOW, TFTP, FTP, SSH, TELNET, HTTP, HTTP2, GRPC, WEBSOCKET, TLS, QUIC, STUN, SIP, RTP, RTSP, SMTP, IMAP, POP3, KERBEROS, LDAP, SMB, NFS, REDIS, MEMCACHED, MYSQL, POSTGRES, MQTT, COAP, AMQP, SSDP, WHOIS, MODBUS, BACNET, DNP3, S7COMM, ETHERNETIP, OPCUA. Every protocol works with zero sub-keywords (emitting smart RFC defaults) and with explicit field overrides.
- **CLI Options**: Support `frameassembly <input.fasm> [-o <output.pcap> | --output <output.pcap>]`, defaulting output to `output.pcap`.
- **Dual-Stack Invariants**: Flows are polymorphic and execute identically over IPv4 and IPv6 host pairs without duplicate definitions. Mixing IPv4 and IPv6 endpoints in the same packet statement is strictly prohibited. Layer 3 controls (`TTL`, `DSCP`, `FLOWLABEL`) are canonical; `FLOWLABEL` is silently ignored on IPv4. Multicast MAC addresses are auto-derived per RFC 2464 (`33:33:xx:xx:xx:xx`) and RFC 1112 (`01:00:5e:xx:xx:xx`).
